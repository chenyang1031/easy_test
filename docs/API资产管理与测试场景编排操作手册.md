## 1. 概述与前置依赖

### 1.1 功能定位


| 模块          | 功能说明                                            |
| ----------- | ----------------------------------------------- |
| **API资产管理** | 集中管理项目下的 API 接口定义，支持导入、分组、编辑、导出，为测试场景提供接口资产基础   |
| **测试场景编排**  | 基于 API 资产编排多接口串联的测试场景，支持变量传递、断言、提取规则，可执行并查看执行日志 |


### 1.2 前置依赖（必读）

在使用「API资产管理」和「测试场景编排」前，需先完成以下配置：


| 依赖菜单   | 说明                                                 |
| ------ | -------------------------------------------------- |
| **项目** | 在「项目」菜单创建项目。API 资产和测试场景均按项目归属                      |
| **环境** | 在「环境」菜单为项目配置运行环境（如开发/测试/预发），包含域名、变量等。测试场景执行时必须选择环境 |


**路径：**

- 项目：左侧导航 → 项目 → 创建项目
- 环境：左侧导航 → 环境 → 创建环境（需关联项目）

## 2. API资产管理

### 2.1 入口与布局

- **入口**：左侧导航 → **API资产管理**
- **布局**：左侧分*组导航* + 右侧接口列表

### 2.2 分组管理

#### 2.2.1 选择项目

1. 在左上角「项目」下拉框选择当前要管理的项目
2. 选择后自动加载该项目的分组树和接口列表
3. 页面会显示项目统计：接口数、分组数、状态分布

#### 2.2.2 分组导航

- **全部接口**：点击根节点可查看项目下所有接口
- **分组筛选**：点击分组名称，仅显示该分组下的接口
- **搜索分组**：在「搜索分组名称」输入框输入关键字，可快速定位分组
- **展开/折叠**：点击分组前的 ▸/▾ 图标展开或折叠子分组

#### 2.2.3 新建分组

1. 点击分组导航区域右上角 **+** 按钮
2. 在弹窗中填写：
  - **分组名称**（必填）
  - **父分组**：选择「根目录」或已有分组
3. 点击「创建」完成

#### 2.2.4 删除分组

1. 在分组导航中选中要删除的分组
2. 点击 **-** 按钮并确认

**说明（与页面行为一致）：**

- 若该分组或其子分组下**仍有关联接口**，系统会**拒绝删除**，并提示需先将接口移动到其他分组、删除接口，或前往支持「删除并迁移至根分组」的分组管理流程处理。
- 仅当分组下**已无任何接口**时，删除才会成功（不会删除接口数据）。
- 在支持迁移的入口中选择「删除并迁移至根分组」时，其下接口会归属到**根目录（未分组）**，而不是在「API 资产管理」本页无提示地自动脱组。

### 2.3 接口列表操作

#### 2.3.1 筛选与搜索

- **搜索**：在搜索框输入关键字，对**接口名称**、**请求 URL** 做模糊匹配（当前列表查询不包含请求参数键值内容的检索）
- **Method 筛选**：下拉选择 GET/POST/PUT/DELETE/PATCH 等
- **状态筛选**：草稿 / 可用 / 已废弃

#### 2.3.2 新增接口

1. 点击右上角「新增接口」按钮
2. 跳转到接口编辑页，填写：
  - 接口名称、请求方式、请求 URL
  - 项目、分组、状态、来源
  - 请求头、请求参数、请求体
  - 响应 Schema 等（详见接口编辑表单）
3. 保存后返回列表

#### 2.3.3 编辑接口

- 点击接口行的 **编辑** 图标，进入接口编辑页
- 页面结构：**上方区域**填写接口名称、Method、URL、项目、分组、状态、来源等基础信息；**下方标签页**为「请求」「响应」「关联」「版本」

#### 2.3.4 复制 URL

- 点击接口行的 **复制** 图标，可将完整请求 URL（含参数）复制到剪贴板

#### 2.3.5 删除接口

- 点击接口行的 **删除** 图标，确认后删除（不可恢复）

### 2.4 批量操作

勾选接口后，会显示批量工具栏，支持：


| 操作       | 说明                                     |
| -------- | -------------------------------------- |
| **批量导出** | 将选中接口导出为 JSON 文件                       |
| **批量删除** | 删除选中的接口                                |
| **改状态**  | 选择目标状态（draft/active/deprecated）后点击「应用」 |
| **移动**   | 选择目标分组后点击「移动」                          |


**拖拽移动**：可将接口行拖拽到左侧分组导航的某个分组上，实现快速移动。

### 2.5 导入 API 资产

导入弹窗提供两种方式：**本地文件导入** 与 **在线导入**。

#### 2.5.1 本地文件导入

1. 在导入弹窗中选择「本地文件导入」标签页
2. 选择 **文件类型**：Postman v2.1 / Apifox JSON / OpenAPI(Swagger)
3. 选择 **文件**：上传本地 JSON 文件
4. 选择 **目标项目** 和 **目标分组**
5. 点击「预览」查看解析结果
6. 若有冲突接口，可设置冲突处理策略（见下方说明）
7. 点击「确认导入」执行导入

#### 2.5.2 在线导入

1. 在导入弹窗中选择「在线导入」标签页
2. 输入 **OpenAPI/Swagger 在线链接**（支持 v1/v2/v3 规范）
3. 选择 **目标项目** 和 **目标分组**
4. 点击「解析链接」自动拉取并解析接口数据
5. 解析完成后进入预览页面，后续流程与本地文件导入一致

**异常提示**：解析失败时会提示明确原因，如「链接无法访问」「格式不支持」「权限不足」等。

#### 2.5.3 冲突处理

- **去重规则**：以「URL + 请求方法（Method）」作为接口唯一标识
- **预览阶段**：
  - 冲突接口会用红色「冲突」标签标注
  - 可查看现有接口名称、更新时间与待导入接口的对比
  - 支持三种冲突处理策略（可批量默认或单条选择）：
    - **覆盖已有**：用待导入接口信息替换现有接口
    - **跳过**：保留现有接口，不导入冲突接口
    - **保留两者**：自动为待导入接口添加后缀（如 `_import_20260311`），避免重复
- **策略记忆**：同批次导入中，默认沿用上次选择的冲突策略
- **确认阶段**：显示「待导入接口总数 / 冲突接口数 / 预计新增接口数」，确认后执行导入

### 2.6 导出 OpenAPI

- 点击「导出OpenAPI」按钮，可将当前项目下所有接口导出为 OpenAPI 格式 JSON 文件

### 2.7 分页

- 底部显示总条数、当前页、总页数
- 可调整每页条数（10/20/50/100）
- 支持上一页/下一页

## 3. 测试场景编排

### 3.1 入口与布局

- **入口**：左侧导航 → **测试场景编排**
- **布局**：场景列表页（默认）→ 场景设计器 → 执行结果页

### 3.2 场景列表页

#### 3.2.1 筛选条件


| 条件       | 说明                          |
| -------- | --------------------------- |
| **当前项目** | 选择要管理的项目。场景按项目归属            |
| **运行环境** | 选择执行时的环境。**执行前必须选择**，否则无法执行 |
| **搜索**   | 按场景名称搜索                     |
| **状态**   | 全部 / 启用 / 禁用                |


**提示**：若未选择项目，会提示「请先在项目管理创建项目」；若项目下无环境，会提示前往「环境」页面创建环境。

#### 3.2.2 场景列表字段


| 列      | 说明                                                             |
| ------ | -------------------------------------------------------------- |
| 名称     | 场景名称；当场景中引用的 API 资产在资产库中发生变更时，可能显示 **「关联API已更新」** 标签（可带涉及节点数量） |
| 描述     | 场景描述                                                           |
| 节点数    | 场景内包含的接口节点数量，可点击查看节点列表                                         |
| 最近执行状态 | 成功 / 失败 / 执行中 / 从未执行                                           |
| 更新时间   | 最后修改时间                                                         |


#### 3.2.3 操作按钮


| 按钮       | 说明                                           |
| -------- | -------------------------------------------- |
| **批量执行** | 勾选多个场景后，选择串行/并发执行方式，批量执行                     |
| **批量删除** | 勾选多个场景后批量删除                                  |
| **回放导入** | 上传 GoReplay .gor 流量文件，解析后创建场景并自动匹配/新建 API 资产 |
| **新增场景** | 创建新场景并进入设计器                                  |


#### 3.2.4 单行操作


| 操作     | 说明                    |
| ------ | --------------------- |
| **执行** | 执行该场景（需已选运行环境，且场景有节点） |
| **编辑** | 进入场景设计器               |
| **日志** | 打开执行日志抽屉，查看历史执行记录     |
| **更多** | 复制场景 / 删除场景           |


### 3.3 场景设计器

#### 3.3.1 进入设计器

- 从列表页点击「新增场景」或「编辑」进入
- 设计器顶部：返回列表、保存场景

#### 3.3.2 场景信息栏

- **场景名称**：可编辑
- **场景描述**：可编辑
- **场景专属环境**：可选「继承全局」或指定环境，用于该场景默认执行环境
- **添加接口**：打开 API 资产选择弹窗

#### 3.3.3 添加接口节点

1. 点击「添加接口」按钮
2. 在弹窗中搜索或选择 API 资产（按分组树展示）
3. 点击接口节点选中
4. 点击「确认添加」完成

**说明**：接口来源于「API资产管理」中当前项目下的接口，未在 API 资产管理中维护的接口无法在此添加。

#### 3.3.4 节点列表

- 表格展示：Method、接口名称、启用状态、操作
- **排序**：左侧拖动手柄支持**拖拽调整节点执行顺序**
- **启用/禁用**：通过开关控制节点是否参与执行
- **编辑**：点击「编辑」选中节点，在右侧配置面板中修改
- **删除**：删除该节点

#### 3.3.5 节点配置面板（右侧）

选中节点后，右侧显示配置面板，包含：

##### 节点信息

- 节点名称、描述
- 失败策略：失败终止 / 失败继续
- 超时时间（秒）

##### 参数配置

- **接口 URL**：只读，来自 API 资产
- **接口专属环境**：可选「继承场景」或指定环境
- **自定义域名**：留空则使用环境域名拼接；若填写完整 URL，优先于环境拼接
- **请求头**：**键值对**表格编辑，可插入变量（无 JSON/键值对模式切换）
- **请求参数**：支持 **JSON** 或 **键值对**（含类型列），可插入变量
- **请求体**：支持 **JSON** 或 **键值对**（含类型列），可插入变量

**变量插入**：点击「插入变量」打开选择器，插入值为 `**{{路径}}`** 形式，常见路径包括：

- **环境变量**：如 `{{env.token}}`（对应环境中配置的变量）
- **场景变量**：如 `{{scene.xxx}}`（与场景变量表中键名一致）
- **前置节点**：如 `{{node_12.extracted.token}}`（`node_` 后为节点 ID 或节点键；提取变量名与「提取规则」中变量名一致；亦可能出现 `node_12.response.status_code` 等预览路径）

具体可选项以当前场景、当前节点、所选环境下的 **变量选择器列表** 为准。

> **💡 提示：JSON 模式中的裸模板语法**
> 在 **JSON 模式**的请求体/请求参数编辑器中（如请求体选择「JSON」格式时），可直接写入 `{{var}}`、`{{func()}}` 等裸模板表达式而**无需用引号包裹**。
> 
> 示例 — 以下配置将自动被正确处理：
> ```json
> {"time": {"value": [{{time1}}], "type": "string"}}
> {"roleIds": [{{roleid}}]}
> ```
> 
> 系统在保存时会自动将裸 `{{...}}` 转为合法的 JSON 字符串 `"{{...}}"`。若需在模板表达式中使用引号（如 `{{func("arg")}}`），系统也会自动转义。
> 
> 若保存时提示「不是合法JSON」，可检查：
> 1. JSON 结构本身是否完整（括号匹配、逗号正确）
> 2. `}}` 是否出现在模板表达式内（如 `{{#if x>y}}`）
> 3. 可先在 JSON 验证器（如 json.cn）中验证结构正确性

##### 响应配置

- **响应预览**：展示上次执行或 Schema 示例
- **提取规则**：从响应中提取字段到变量池，供后续节点使用
  - 变量名：如 `token`
  - 路径：与执行引擎一致，**响应体挂在 `response` 下**（即 JSON 根字段），如 `$.response.data.token`。不要写成 `$.response.body.xxx`（除非接口 JSON 里真的存在名为 `body` 的字段）。

##### 断言规则

- 校验维度：字段路径，如 `$.status_code`、`$.response.code`
- 操作符：等于、不等于、包含、大于、小于等
- 期望值
- 失败策略：**失败终止**（断言未通过则整节点失败）/ **失败继续**（仅记录断言失败，整节点仍可计为通过，用于非关键检查）
- 支持模板：状态码 200、业务 code=200 等

**说明**：节点是否成功 = **HTTP 状态码与节点「预期状态码」一致**，且 **每条「失败终止」的断言都通过**。若某条断言设为 **失败继续**，则该条未通过时**不会**把整节点判失败——执行页会显示 **passed(断言未通过)** 并解释原因；若希望业务字段（如 `msg`）不对则节点失败，请对该条使用 **失败终止**。路径或期望值写错时，也会出现「HTTP 200 但断言红字」——以日志中的期望/实际为准排查。

**变量解析失败提示优化**：当节点配置或断言规则中的 `{{var}}` 变量路径在变量池中不存在时，错误信息会自动标识**具体字段**。例如 `「断言规则-状态码校验」中变量解析失败: 变量路径不存在: time` 表示断言规则「状态码校验」中引用了变量 `time` 但该变量尚未定义，无需逐个字段排查。

### 3.4 执行与结果

#### 3.4.1 执行场景

1. 在场景列表页选择「运行环境」
2. 点击场景的「执行」按钮
3. 等待本次执行结束后，自动**跳转执行结果页**查看该次执行的汇总与节点详情（执行过程中列表行可显示执行中状态）

**批量执行**：勾选多个场景并批量执行时，在列表页等待全部完成后提示结果，**不自动跳转**至某一执行结果页；需对单个场景点「执行」或通过「日志」查看记录。

#### 3.4.2 执行结果页

- 显示：状态、成功节点数、失败节点数、耗时
- **场景执行状态**除「成功 / 失败 / 执行中」外，另有 **「部分成功」**（`partial_success`）：全部节点已跑完且无**硬失败**节点，但存在 **「失败继续」** 策略下仍未通过的断言。此时节点卡片仍为 `passed`，但整场景不算完全成功。
- 节点执行日志：请求/响应、断言结果、提取结果
- 历史执行记录：可切换查看不同执行记录

#### 3.4.3 执行日志抽屉

- 在列表页点击「日志」打开
- 左侧：历史执行记录列表
- 右侧：选中记录的节点执行详情

## 4. 菜单联动关系

### 4.1 直接联动


| 模块      | 依赖的菜单       | 说明              |
| ------- | ----------- | --------------- |
| API资产管理 | **项目**      | 接口按项目归属，需先有项目   |
| 测试场景编排  | **项目**      | 场景按项目归属         |
| 测试场景编排  | **环境**      | 执行时必须选择环境       |
| 测试场景编排  | **API资产管理** | 场景节点从 API 资产中选择 |


### 4.2 数据流向

```
项目 → 环境（配置域名、变量）
  ↓
项目 → API资产管理（分组、接口定义）
  ↓
项目 → 测试场景编排（选择 API 资产作为节点，选择环境执行）
```

### 4.3 其他相关菜单


| 菜单       | 与 API/场景 的关系            |
| -------- | ----------------------- |
| **测试用例** | 独立模块，可单独编写用例，与场景编排无直接关联 |
| **测试套件** | 可组织多个测试用例，与「定时任务」关联     |


**说明**：当前「定时任务」基于「测试套件」执行，不支持直接选择「测试场景」作为定时任务目标。如需定时执行场景，需通过其他方式（如外部调度）实现。

## 5. 典型工作流

### 5.1 从零搭建 API 测试场景

1. **项目管理**：创建项目
2. **环境配置**：在「环境」中为该项目创建环境（如开发环境），配置 base_url、变量
3. **API 资产**：在「API资产管理」中导入或手工添加接口，建立分组
4. **场景编排**：在「测试场景编排」中选择项目 → 新增场景 → 添加接口节点 → 配置参数、断言、提取规则
5. **执行验证**：选择运行环境 → 执行场景 → 查看执行结果

### 5.2 环境前置脚本（兼容 Postman/Apifox）

1. 进入「环境」→ 选择环境 → 详情页 →「前置脚本」标签
2. 编写 JS 脚本，支持：
  - **pm.environment**：读写环境变量（临时生效）
  - **pm.variables** / **pm.collectionVariables**：临时变量
  - **pm.request**：url、method、headers（get/set/has/remove/add）、params、body
  - **CryptoJS**：MD5、HmacSHA256 等加密封装
  - **console.log/warn/error**：调试输出（测试脚本时可查看）
3. 点击「测试脚本」模拟执行，查看变量变更和 Console 输出
4. 保存后，该环境下所有接口请求前会自动执行脚本

### 5.3 导入 Postman / OpenAPI 后编排场景

1. 在「API资产管理」中点击「导入」
2. **本地导入**：选择 Postman v2.1 / OpenAPI，上传 JSON 文件；或 **在线导入**：输入 OpenAPI/Swagger 链接并解析
3. 选择目标项目和分组，预览解析结果；若有冲突接口，选择处理策略（覆盖/跳过/保留两者）
4. 确认导入
5. 导入完成后，在「测试场景编排」中新增场景，从「添加接口」弹窗中选择刚导入的接口
6. 编排顺序、配置变量传递和断言后执行

### 5.4 多接口串联（变量传递）

1. 在场景设计器中添加多个接口节点（可用拖拽调整顺序）
2. 前置节点：在「响应配置」中配置提取规则，如变量名 `token`，路径 `$.response.data.token`（按实际 JSON 结构调整）
3. 后续节点：在「参数配置」的请求头、参数或请求体中，通过「插入变量」选择 `{{node_<id>.extracted.token}}` 等路径，或手写与变量池一致的 `{{...}}` 表达式
4. 保存并执行，系统按节点顺序执行并解析变量

### 5.5 从 GoReplay 回放导入场景

1. 使用 GoReplay 录制流量：`gor --input-raw :80 --output-file requests.gor`
2. 在「测试场景编排」列表页点击「回放导入」
3. 上传 .gor 或 .gor.gz 文件，选择目标项目、分组、场景名称
4. 点击「解析预览」，查看解析出的请求列表及与 API 资产的匹配状态（已匹配 / 待新增）
5. 勾选要导入的请求，点击「确认导入」
6. 系统自动创建场景，未匹配的接口会新建为 API 资产（来源：GoReplay），导入完成后跳转至场景设计器
