# EasyTesting UI 自动化使用手册

## 一、功能概述

UI 自动化模块基于 Playwright 浏览器自动化引擎，支持对 Web 应用进行自动化测试。核心能力包括：

- 页面元素管理：维护被测系统的页面和元素定位信息
- 用例编排：通过步骤组合编排测试用例
- 自动化执行：支持单用例执行和批量执行
- AI 浏览器测试：自然语言驱动的智能浏览器自动化
- 定时任务：支持 Cron/间隔/单次触发的定时执行
- 执行报告：Trace 录制、截图、视频回放

支持浏览器：**Chromium**、**Firefox**、**WebKit**

## 三、使用流程

### 3.1 选择项目

进入 UI 自动化页面后，右上角有项目选择器。所有数据（模块、页面、元素、用例等）均按项目隔离，操作前请先选择目标项目。

页面顶部展示当前项目的统计卡片：模块数、页面数、元素数、用例数、执行次数、通过率。

### 3.2 管理模块（左侧模块树）

左侧面板为模块树，用于组织页面和元素。

**新增模块：**
1. 点击左上角「+ 新增」按钮
2. 填写模块名称
3. 选择父模块（不选则为顶级模块）
4. 点击「确定」

**拖拽排序：** 模块节点支持拖拽，拖入另一个节点内部表示成为其子节点，拖到后面表示排在同级之后。

### 3.3 管理页面（页面管理 Tab）

页面代表被测系统中的一个 URL 地址，元素归属于页面。

**新增页面：**
1. 切换到「页面管理」Tab
2. 点击「+ 新增页面」
3. 填写：
   - 名称：页面名称（如"登录页"）
   - URL：页面的完整地址（如 `https://example.com/login`）
   - 模块：关联到模块树中的某个模块
   - 描述：备注说明
4. 点击「保存」

### 3.4 管理元素（元素管理 Tab）

元素代表页面上的可操作控件（按钮、输入框、链接等），通过定位策略来识别。

**新增元素：**
1. 切换到「元素管理」Tab
2. 点击「+ 新增元素」
3. 填写：
   - 名称：元素名称（如"登录按钮"）
   - 元素类型：input / button / link / dropdown / checkbox / radio / text / image / container / table / form / modal
   - 定位类型：css / xpath / text / role / label / placeholder / testid / id / name
   - 定位值：对应的定位表达式
   - 页面：关联到某个页面
4. 点击「保存」

**9 种定位策略说明：**

| 定位类型 | 说明 | 示例 |
|---------|------|------|
| css | CSS 选择器 | `#login-btn` / `.submit-btn` |
| xpath | XPath 表达式 | `//button[@type='submit']` |
| text | 文本内容 | `登录` |
| role | ARIA 角色 | `button` / `link` / `textbox` |
| label | 关联 label 文本 | `用户名` |
| placeholder | placeholder 属性 | `请输入用户名` |
| testid | data-testid 属性 | `login-submit-btn` |
| id | ID 属性 | `login-btn` |
| name | name 属性 | `username` |

**元素验证：** 每个元素右侧有「验证」按钮，点击后系统会尝试用当前环境配置定位该元素，验证结果标记为：有效（绿色）/ 无效（红色）/ 待验证 / 未知。

**多定位器降级：** 元素支持配置最多 3 组定位器（locator_type + locator_value），执行时按顺序尝试，第一个成功的定位器生效，提高稳定性。

### 3.5 管理环境配置（环境配置 Tab）

环境配置定义了测试执行时的浏览器参数。

**新增环境：**
1. 切换到「环境配置」Tab
2. 点击「+ 新增环境」
3. 配置参数：

| 参数 | 说明 | 默认值 |
|------|------|--------|
| 名称 | 环境名称 | - |
| 基础 URL | 被测系统地址 | - |
| 浏览器 | chromium / firefox / webkit | chromium |
| 无头模式 | 是否隐藏浏览器窗口 | 是 |
| 视口宽度 | 浏览器宽度（px） | 1920 |
| 视口高度 | 浏览器高度（px） | 1080 |
| 超时 | 操作超时时间（秒） | 30 |
| 默认环境 | 标记为默认 | 否 |

4. 点击「保存」

**建议：** 至少创建一个环境配置，执行用例时需要指定环境 ID。

### 3.6 管理公共数据（公共数据 Tab）

公共数据是项目级别的共享变量，执行时自动加载到上下文中，可在步骤中通过变量引用。

**支持的类型：** 字符串、整数、列表、字典

**使用方式：** 在步骤的值字段中用 `{{变量key}}` 引用。

### 3.7 创建测试用例（测试用例 Tab）

测试用例由多个步骤组成，按顺序执行。

**新增用例：**
1. 切换到「测试用例」Tab
2. 点击「+ 新增用例」
3. 填写：
   - 名称：用例名称
   - 级别：P0（核心）/ P1（重要）/ P2（一般）/ P3（低优）
   - 描述：用例说明
   - 前置 SQL：执行前运行的 SQL（需环境启用数据库）
   - 后置 SQL：执行后运行的 SQL
4. 点击「保存」

**步骤类型（6 种）：**

| 类型 | 说明 | 适用场景 |
|------|------|---------|
| 元素操作 | 对页面元素执行动作 | 点击、填写、选择等 |
| 断言 | 验证页面状态 | 文本校验、可见性、属性值 |
| SQL 操作 | 执行数据库 SQL | 数据准备、数据清理 |
| 自定义变量 | 设置运行时变量 | 中间结果传递 |
| 条件逻辑 | 条件判断 | 分支执行、跳过、中断 |
| Python 代码 | 执行 Python 片段 | 复杂逻辑处理 |

**元素操作支持的动作：**

| 动作 | 说明 |
|------|------|
| click | 点击元素 |
| fill | 填充输入框（清空后写入） |
| type | 逐字符输入 |
| select | 下拉选择 |
| check | 勾选复选框 |
| uncheck | 取消勾选 |
| hover | 鼠标悬停 |
| get_text | 获取元素文本 |
| get_attribute | 获取元素属性 |
| upload | 上传文件 |
| press_key | 按键操作（如 Enter、Tab） |
| wait_visible | 等待元素可见 |
| wait_hidden | 等待元素隐藏 |

**断言类型：**

| 断言 | 说明 |
|------|------|
| assert_text | 元素文本包含指定内容 |
| assert_visible | 元素可见 |
| assert_enabled | 元素可用（非禁用） |
| assert_attribute | 元素属性等于指定值（格式：`attr_name=expected_value`） |

### 3.8 执行测试

**单用例执行：**
1. 在用例列表中找到目标用例
2. 点击「执行」按钮
3. 输入环境配置 ID（如 `1`）
4. 确认执行

**批量执行：**
1. 勾选多个用例（表格左侧复选框）
2. 点击「批量执行」按钮
3. 输入环境配置 ID
4. 确认执行

**执行特性：**
- 异步执行，提交后立即返回
- 执行过程中自动录制 Trace
- 失败时自动截图
- 支持步骤级错误重试
- 执行完毕自动关闭浏览器

### 3.9 查看执行记录（执行记录 Tab）

切换到「执行记录」Tab 查看所有批次的执行结果。

**筛选条件：** 按状态筛选（待执行 / 执行中 / 成功 / 失败 / 部分成功）

**详情查看：** 点击「详情」按钮展开抽屉面板，显示：
- 批次基本信息（状态、通过率、耗时）
- 每条用例的执行结果（通过/失败/耗时/错误信息）

## 四、AI 浏览器测试

入口：侧边栏 **UI自动化** > **AI智能用例**

AI 用例使用自然语言描述测试任务，由 AI 驱动浏览器自动理解和执行。

**创建 AI 用例：**
1. 点击右上角「+ 新增AI用例」
2. 填写用例名称
3. 在「任务描述」中用自然语言描述测试步骤，例如：
   ```
   打开登录页面，输入用户名admin和密码123456，点击登录按钮，
   验证页面跳转到首页，页面标题包含"首页"
   ```
4. 可选添加标签
5. 点击「保存」

**执行与历史：**
- 点击「执行」提交 AI 用例执行
- 点击「历史」查看执行记录（状态、Token 消耗、耗时）
- 执行中的任务可以「停止」
- 执行完成后可查看「报告」

## 五、定时任务

入口：侧边栏 **UI自动化** > **UI定时任务**

**创建定时任务：**
1. 点击「+ 新增任务」
2. 填写：
   - 任务名称
   - 触发类型：
     - **Cron 表达式**：如 `0 2 * * *`（每天凌晨 2 点）
     - **固定间隔**：如每 3600 秒（1 小时）
     - **单次执行**
   - 浏览器类型
   - 无头模式
   - 失败/成功通知开关
3. 点击「保存」

**任务管理：**
- 开关控制是否启用
- 「立即执行」手动触发一次
- 显示成功/失败/总执行次数统计

## 六、执行引擎技术说明

### 架构

```
前端提交执行 → Django API → Celery 异步任务 → UIExecutor → PlaywrightEngine → Playwright 浏览器
```

### 定位降级机制

每个元素最多配置 3 组定位器，执行时按顺序尝试：

1. 尝试第 1 组定位器，等待元素可见
2. 失败则尝试第 2 组定位器
3. 再失败则尝试第 3 组定位器
4. 全部失败则步骤报错

### 变量系统

- **公共变量**：从公共数据自动加载
- **自定义变量**：通过步骤设置
- **SQL 结果**：`__sql_result__` 存储 SQL 查询结果
- **操作结果**：`__last_result__` 存储上一步操作返回值
- **变量引用**：在值字段中用 `{{变量名}}` 引用

### 条件逻辑

支持的条件运算符：`==`、`!=`、`contains`、`not_contains`、`>`、`<`、`>=`、`<=`

条件不满足时：
- `skip`：跳过后续步骤
- `abort`：直接中断用例执行

### Python 代码执行

可在步骤中编写 Python 代码片段，运行环境中可使用：
- `variables`：运行时变量字典
- `json`：JSON 模块
- 基础内置函数：`print`、`len`、`str`、`int`、`float`、`list`、`dict`、`bool`、`range`、`enumerate`、`zip`、`min`、`max`、`sum`、`abs`

## 七、快速上手示例

### 场景：测试登录功能

**步骤 1：创建环境**
- 名称：测试环境
- 基础 URL：`https://your-app.com`
- 浏览器：chromium
- 无头模式：是

**步骤 2：创建模块**
- 模块名：用户模块

**步骤 3：创建页面**
- 名称：登录页
- URL：`https://your-app.com/login`
- 模块：用户模块

**步骤 4：创建元素**

| 元素名 | 类型 | 定位类型 | 定位值 |
|--------|------|---------|--------|
| 用户名输入框 | input | placeholder | 请输入用户名 |
| 密码输入框 | input | placeholder | 请输入密码 |
| 登录按钮 | button | text | 登录 |
| 首页标题 | text | css | .page-title |

**步骤 5：创建测试用例**
- 名称：正常登录测试
- 级别：P0

**步骤 6：添加步骤**
1. 元素操作 → 用户名输入框 → fill → `admin`
2. 元素操作 → 密码输入框 → fill → `password123`
3. 元素操作 → 登录按钮 → click
4. 断言 → 首页标题 → assert_text → `首页`

**步骤 7：执行**
- 点击用例的「执行」按钮
- 输入环境 ID
- 等待执行完成
- 在执行记录中查看结果

## 八、常见问题

**Q：执行时提示"身份认证信息未提供"？**
A：请先登录系统，UI 自动化 API 需要认证。

**Q：元素验证显示"无效"？**
A：检查定位策略和定位值是否正确，确保被测页面可以正常访问。

**Q：批量执行后如何查看结果？**
A：切换到「执行记录」Tab，找到对应批次，点击「详情」查看每条用例的执行情况。

**Q：如何在步骤之间传递数据？**
A：使用「自定义变量」步骤设置变量，后续步骤用 `{{变量名}}` 引用。

**Q：支持 iframe 中的元素吗？**
A：支持。元素模型中有 `iframe_locator` 字段，配置 iframe 的定位器后，引擎会先切换到 iframe 再定位目标元素。

**Q：执行失败有截图吗？**
A：有。执行引擎在步骤失败时自动截图，截图保存在 `media/ui_screenshots/` 目录下，并在执行记录中关联展示。
