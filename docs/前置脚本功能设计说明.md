# 前置脚本功能设计说明

## 一、功能概述

**前置脚本**（Pre-request Script）是 EasyTesting 环境模块中的一项能力，允许在**发送 HTTP 请求之前**执行一段 JavaScript 代码，用于动态修改请求头、请求参数、请求体或环境变量。设计上兼容 **Postman / Apifox** 的 `pm` 对象 API，便于用户从现有工具迁移脚本。

### 核心价值

- **Token 刷新**：从环境变量读取 token，自动写入 `Authorization` 头
  - `pm.environment.get('token')` 读取的是【环境】→ 编辑 →「环境变量 (JSON)」中配置的 `token` 键
  - 需在环境编辑页配置 `{"token": "your_token_value"}` 并保存
- **签名生成**：按业务规则生成时间戳、签名等参数
- **请求预处理**：统一添加 X-Request-Id、X-Client 等通用请求头
- **变量计算**：基于已有变量计算新值，供后续请求使用

## 二、设计思路

### 2.1 兼容性优先

采用与 Postman/Apifox 一致的 `pm` 对象设计，降低学习成本：

| 对象/方法 | 作用 |
|----------|------|
| `pm.environment` | 读写环境变量（get/set/unset/toObject） |
| `pm.variables` | 临时变量存储 |
| `pm.collectionVariables` | 集合级变量（映射到 variables） |
| `pm.request.headers` | 修改请求头（get/set/unset/has/remove/add） |
| `pm.request.params` | 修改 URL 查询参数 |
| `pm.request.body` | 修改请求体 |
| `pm.test` / `pm.expect` | 空实现，避免脚本报错 |
| `console.log/warn/error` | 输出可被捕获用于调试 |
| `CryptoJS` | MD5、HmacSHA256 等加密封装 |

### 2.2 安全约束

- **禁止网络请求**：脚本在沙箱中执行，无法发起 HTTP 请求
- **禁止文件操作**：无文件系统访问能力
- **超时限制**：默认 1000ms，最大 1000ms，防止死循环

### 2.3 作用域与优先级

前置脚本绑定在**环境（Environment）**上，在**测试场景编排**执行时生效。环境优先级为：

```
接口专属环境 > 场景环境 > 全局环境
```

## 三、实现架构

### 3.1 模块划分

```
test_manager/
├── pre_request_script.py          # 核心执行逻辑
├── pre_request_script_runner.py   # 子进程隔离执行器（Windows 兼容）
├── pre_request_script_libs/
│   └── crypto-js.min.js           # CryptoJS 库
└── api/
    ├── views.py                   # 测试脚本 API
    └── scene_engine.py            # 场景执行时调用
```

### 3.2 数据流

```
┌─────────────────────────────────────────────────────────────────────────┐
│                          前置脚本执行流程                                  │
└─────────────────────────────────────────────────────────────────────────┘

【编辑/测试场景】
  用户输入脚本 + 环境变量
        │
        ▼
  _build_full_script()  ──►  注入 CryptoJS + pm 对象 + 用户脚本
        │
        ▼
  MiniRacer.execute()   ──►  V8 引擎执行 JS
        │
        ▼
  返回 __pm_result__    ──►  { env, request, variables, logs }
        │
        ▼
  解析并应用变更        ──►  更新 headers / params / body / variables

【实际请求场景】
  场景引擎渲染请求 ──► 获取生效环境 ──► execute_pre_request_script()
        │
        ▼
  应用脚本变更后的 headers/params/body ──► 发起 HTTP 请求
```

## 四、核心实现逻辑

### 4.1 `_build_full_script()` 脚本构建

将用户脚本包装在 IIFE 中，注入：

1. **环境数据**：`_env`、`_req`、`_vars`、`_coll` 等 JSON 序列化后的初始数据
2. **console 重写**：将 log/warn/error 输出收集到 `_logs` 数组
3. **CryptoJS**：加载 crypto-js.min.js，提供 MD5、HmacSHA256 等
4. **pm 对象**：所有 get/set 操作映射到上述内部变量
5. **用户脚本**：在 `"use strict"` 下执行，异常被捕获并写入 `__pm_result__.error`

最终返回 `__pm_result__`，包含 `env`、`request`、`variables`、`logs`。

### 4.2 `execute_pre_request_script()` 主执行函数

**输入**：脚本、环境变量、请求头/参数/体、请求 URL/方法、超时时间等

**处理**：

1. 空脚本直接返回，不做处理
2. 检查 `py_mini_racer` 是否安装
3. 将 body 转为 Apifox 兼容结构（raw/urlencoded/formdata）
4. 调用 `_build_full_script()` 生成完整 JS
5. 使用 `MiniRacer().execute()` 执行，超时抛出 `JSTimeoutException`
6. 解析返回的 `__pm_result__`，将 Apifox body 转回内部格式
7. 返回 `(new_env, new_headers, new_params, new_body, new_vars, logs)`

### 4.3 `test_pre_request_script()` 测试脚本

用于前端「测试脚本」功能，模拟执行并返回**变量变更日志**和 **console 输出**：

- 使用固定模拟请求：`Content-Type: application/json`、空 body
- 调用 `execute_pre_request_script()` 得到结果
- 对比执行前后，生成 `logs` 数组（type: environment/header/param/variable）
- 返回 `{ success, logs, console, error }`

### 4.4 子进程隔离（Windows 兼容）

`py_mini_racer` 在 Windows 上使用 V8 原生引擎，可能发生**原生崩溃**导致 Django 进程退出。因此「测试脚本」通过**子进程**执行：

1. **pre_request_script_runner.py**：从 stdin 读取 `{ script, env_vars, timeout_ms }`，调用 `test_pre_request_script()`，向 stdout 输出 JSON
2. **API 视图**：`subprocess.run()` 启动子进程，设置 `PYTHONIOENCODING=utf-8` 避免编码问题，15 秒超时
3. 子进程崩溃或超时，主进程继续运行，返回错误信息给前端

## 五、使用场景

### 5.1 环境详情页

- **路径**：环境 → 选择环境 → 详情页 →「前置脚本」标签
- **功能**：
  - CodeMirror 编辑器编写脚本
  - 插入代码片段：Token 刷新、签名生成、请求头添加
  - **测试脚本**：模拟执行，展示变量变更和 console 输出
  - **保存**：PATCH `/api/environments/{id}/` 更新 `pre_request_script`

### 5.2 测试场景编排

- **执行时机**：每个节点发起 HTTP 请求**之前**
- **调用位置**：`scene_engine.py` 中 `execute_scene()` 的节点循环内
- **流程**：
  1. 按优先级获取 `effective_env`（接口专属 > 场景 > 全局）
  2. 若有 `pre_request_script`，将当前变量池、渲染后的 headers/params/body 传入
  3. 执行脚本，得到 `new_env`、`new_headers`、`new_params`、`new_body`、`new_vars`
  4. 更新变量池，用新值覆盖请求数据
  5. 若脚本执行失败，节点标记为 failed，按 `on_failed` 策略决定是否继续

## 六、API 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/environments/{id}/test-pre-request-script/` | 测试脚本（子进程执行） |
| PATCH | `/api/environments/{id}/` | 保存脚本（含 `pre_request_script` 字段） |

---

## 七、数据模型

**Environment** 模型字段：

- `pre_request_script`：Text 类型，JS 脚本内容
- `script_timeout`：Integer，超时毫秒（100–1000，默认 1000）

---

## 八、扩展预留

- **API 资产级前置脚本**：当前仅环境级，可扩展为接口级
- **节点级前置脚本**：单节点可覆盖环境脚本
- **js2py 备选**：若 `py_mini_racer` 在部分环境不可用，可考虑纯 Python 的 js2py 作为 fallback
