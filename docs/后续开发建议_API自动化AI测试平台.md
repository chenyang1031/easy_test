# EasyTesting API 自动化 AI 测试平台 — 后续开发建议

> **生成日期**：2026 年 6 月 3 日  
> **定位**：基于当前平台能力，面向 API 自动化 AI 测试方向的发展路线图

---

## 一、当前能力盘点

| 能力 | 成熟度 | 说明 |
|------|--------|------|
| API 资产中心化管理 | ★★★★★ | 完整的 CRUD + 导入导出 + 版本历史 + 变更追踪 |
| 可视化场景编排 | ★★★★☆ | 拖拽式设计器 + 变量传递 + 断言 + 参数提取 |

| 提示词模板管理 | ★★★★☆ | 分类管理 + 变量替换 + 系统默认模板 |
| 性能压测 | ★★★★☆ | Locust 集成 + 多阶段负载 + 实时监控 |
| 流量回放 | ★★★☆☆ | GoReplay/HAR 解析 + 场景生成 |
| 前置脚本 | ★★★☆☆ | js2py + Postman 兼容 API |
| 定时任务 | ★★★☆☆ | Celery Beat + 邮件通知 |

### 需补齐的关键短板
| 短板 | 影响 |
|------|------|
| 无 CI/CD 集成（CLI/API 触发） | 无法嵌入 DevOps 流水线 |
| 无测试用例版本化 | 用例变更历史无法追溯 |
| 无团队协作功能 | 角色权限缺失 |

## 二、开发路线图总览

### Phase 1：平台基座夯实（1-2 月）
> 安全性、稳定性、可维护性 — 为后续功能打好地基

### Phase 2：AI 能力深化（2-3 月）
> 让 AI 不仅生成用例，而是贯穿测试全生命周期

### Phase 3：DevOps 集成（3-4 月）
> 从"平台内测试"到"嵌入研发流水线"

### Phase 4：智能化测试（4-6 月）
> 智能失败分析、自愈测试、风险预测

## 四、Phase 2：AI 能力深化

### 4.1 AI 智能失败诊断 ⭐ 核心新功能

**场景**：测试失败后，AI 自动分析失败原因并给出修复建议。

**功能设计**：
```
测试失败 → 自动收集上下文（请求/响应/断言/错误信息）
        → 发送给 AI 模型分析
        → 生成诊断报告：
          - 失败原因分类（参数错误/接口变更/环境问题/业务逻辑变更）
          - 修复建议（更新断言值/调整参数/检查环境变量）
          - 置信度评分
```

| 任务 | 工作量 |
|------|--------|
| 失败上下文收集器 | 2天 |
| AI 诊断提示词模板 | 1天 |
| 诊断结果展示（前端） | 2天 |
| 诊断历史与反馈（点赞/点踩优化提示词） | 2天 |

### 4.2 AI 智能测试用例生成 v2

**目标**：从"选接口→生成用例"升级为"选业务场景→AI 拆解→生成多接口联调用例"

| 任务 | 说明 | 工作量 |
|------|------|--------|
| 场景描述→用例拆解 | 用户用自然语言描述业务场景（如"用户登录后下单并支付"），AI 拆解为 API 调用链 | 3天 |
| 多接口联调生成 | AI 生成多个用例并自动设置变量提取和传递 | 3天 |
| 接口依赖智能推断 | 分析 API 资产的参数和响应结构，推断参数来源依赖 | 2天 |
| 测试数据智能推荐 | AI 根据参数类型/约束生成合理的测试数据 | 2天 |

### 4.3 AI 接口变更影响分析

**场景**：API 资产变更后，AI 分析受影响的范围并自动更新关联用例。

| 任务 | 工作量 |
|------|--------|
| 变更 Diff → AI 分析影响的用例和场景节点 | 2天 |
| AI 自动生成更新建议（断言值调整/参数更新） | 2天 |
| 受影响场景节点自动标记"需审查" | 1天 |

### 4.4 提示词 A/B 测试

**目标**：不同提示词模板的生成效果量化对比。

| 任务 | 说明 | 工作量 |
|------|------|--------|
| 提示词效果评分 | 用户对生成用例点赞/采纳率统计 | 2天 |
| A/B 对比 | 同一接口用两个模板生成，对比采纳率 | 2天 |
| 提示词优化建议 | AI 分析低评分模板并建议改进 | 2天 |

### 4.5 知识库积累（RAG）

**场景**：将历史通过的测试用例、常见 Bug 模式、业务规则沉淀为知识库，AI 生成时参考。

| 任务 | 说明 | 工作量 |
|------|------|--------|
| 测试用例向量化 | 将历史用例转为向量存储（如 ChromaDB） | 3天 |
| 生成时 RAG 增强 | 生成时检索相似接口的历史用例作为 Few-shot | 3天 |
| Bug 模式库 | 从失败用例中提取常见 Bug 模式，注入生成规则 | 2天 |

## 五、Phase 3：DevOps 集成

### 5.1 CLI 工具与 CI/CD 触发

**目标**：测试场景可以从命令行触发，集成到 CI/CD 流水线。

```bash
# CLI 触发场景执行
easytesting run --scene-id 5 --env-id 2 --wait --output report.json

# CI 中使用
easytesting run --scene-id 5 --exit-code  # 失败时返回非零退出码
```

| 任务 | 说明 | 工作量 |
|------|------|--------|
| CLI 工具（click/typer） | `easytesting run/report/import` 命令 | 3天 |
| API Token 认证 | 支持 API Token 方式调用（非 Session），用于 CI | 2天 |
| Webhook 回调 | 执行完成后回调通知 CI 系统 | 1天 |
| GitLab CI / GitHub Actions 模板 | 提供开箱即用的 Pipeline 配置 | 1天 |

### 5.2 API 契约测试（Contract Testing）

**目标**：验证 API 实现与其定义（API 资产中的 Schema）一致。

| 任务 | 说明 | 工作量 |
|------|------|--------|
| 响应 Schema 自动校验 | 执行时自动对比响应结构与 ApiAsset.response_schema | 2天 |
| 契约测试模式 | 专门校验接口实现是否符合定义的测试模式 | 2天 |
| OpenAPI 规范导出 | 将 API 资产导出为标准 OpenAPI 3.0 规范 | 2天 |

### 5.3 API 监控（Synthetic Monitoring）

**目标**：定时对核心 API 进行健康检查，与定时任务不同（更轻量、更快）。

| 任务 | 说明 | 工作量 |
|------|------|--------|
| API 监控任务 | 轻量级定时探测（仅验证状态码+响应时间+基本断言） | 2天 |
| 监控大盘 | 展示核心 API 健康状态、响应时间趋势 | 2天 |
| 告警规则 | 连续失败 N 次/响应时间超过阈值时触发告警 | 1天 |

## 六、Phase 4：智能化测试

### 6.1 自愈测试（Self-Healing Tests）

**场景**：接口发生非破坏性变更（如字段重命名、新增必填参数）时，自动修复测试用例。

| 任务 | 说明 | 工作量 |
|------|------|--------|
| 失败模式识别 | 区分"接口真Bug"和"接口合理变更导致的用例失效" | 3天 |
| 自动修复建议 | 对合理的接口变更，AI 自动更新断言值/参数 | 3天 |
| 半自动修复 | 修复建议经用户确认后批量应用 | 2天 |

### 6.2 智能回归测试选择

**场景**：代码变更后，AI 分析变更范围，只运行相关的测试场景（而非全部），缩短回归时间。

| 任务 | 工作量 |
|------|--------|
| 代码变更→API 变更关联分析 | 3天 |
| 测试场景风险评分 | 2天 |
| 最小回归集推荐 | 2天 |

### 6.3 智能 Mock 服务

**场景**：测试依赖的外部 API 不可用或不稳定时，AI 根据 API 定义自动生成 Mock 响应。

| 任务 | 说明 | 工作量 |
|------|------|--------|
| AI Mock 生成 | 根据 response_schema 生成真实感的 Mock 数据 | 3天 |
| Mock 规则引擎 | 请求匹配 → 动态响应（支持状态码/延迟/场景模拟） | 3天 |
| Mock 服务独立部署 | 将 Mock 服务独立部署为轻量 HTTP Server | 2天 |

### 6.4 测试覆盖率智能分析

| 任务 | 说明 | 工作量 |
|------|------|--------|
| API 级覆盖率 | 哪些 API 资产有测试覆盖，哪些没有 | 2天 |
| 参数级覆盖率 | 每个参数的哪些值被测试过（边界/异常/正常） | 3天 |
| 覆盖率缺口建议 | AI 分析未覆盖的 API 和参数，建议补充测试 | 2天 |

## 八、推荐优先级排序

### 立即可做（1-2 周内，高 ROI）
1. **安全加固**（环境变量 + DEBUG + 频率限制）— 零功能依赖，纯配置改动
2. **Docker 容器化** — 降低新成员上手成本
3. **API 文档生成** — 提升前后端协作效率
4. **前端公共代码提取** — 减少后续开发重复

### 短期重点（1-2 月）
5. **AI 智能失败诊断** — 这是"AI 测试平台"区别于传统测试平台的杀手级功能
6. **CLI 工具 + CI/CD 集成** — 从"工具"变成"平台"的关键一步
7. **核心模块单元测试** — 质量底座
8. **数据库迁移 PostgreSQL** — 为多用户和更大的数据量做准备

### 中期规划（3-4 月）
9. **AI 用例生成 v2**（场景描述→链路生成）
10. **API 契约测试**（Schema 校验 + OpenAPI 导出）
11. **RAG 知识库**（历史用例增强生成）
12. **API 监控**（Synthetic Monitoring）

### 长期愿景（4-6 月）
13. **自愈测试** — 接口变更时自动修复用例
14. **智能回归选择** — 最小回归集推荐
15. **智能 Mock 服务** — 外部依赖模拟
16. **测试覆盖率智能分析** — 覆盖缺口自动发现
