# 多阶段负载 — 技术选型说明（阶段2 单机）

## 目标

在**单机 Locust** 下按阶段改变并发用户数与用户生成速率，且：

- 不中断统计（同一 `Environment` / `stats` 累计）
- 与无 `stages` 的旧任务兼容（仍使用 `runner.start(users, spawn_rate)` + 定时 `quit`）

## 选型：Locust `LoadTestShape`

采用官方 **`LoadTestShape`**：`tick()` 根据 `get_run_time()` 返回当前阶段应达到的 `(user_count, spawn_rate)`，返回 `None` 时结束压测。

### 为何不用多次 `runner.quit()` 再 `start()`

- 重启 runner 会重置或割裂统计，难以满足「统计数据连续」的验收要求。
- `LoadTestShape` 由 Locust 内部调度用户增减，与单机 `LocalRunner` 配套成熟。

### 与 `run_time` 的关系

配置校验要求：`sum(stages[].duration_sec) == PerformanceTestTask.run_time`。  
`tick()` 在时间轴上依次消费各阶段时长；总时长与任务字段一致，便于与采集循环、任务状态对齐。

### 阶段3 扩展

分布式场景下可使用 **Master/Worker** 或 **多进程 Locust**；负载形态仍可复用 `LoadTestShape` 思路，在 Master 侧统一 `tick`，或改为向 Workers 广播目标并发。实现应放在独立模块，避免修改单机分支逻辑。
