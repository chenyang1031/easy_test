# 性能测试阶段2 — 验收用例（建议）

## 指标与报告（D1）

| 编号 | 场景 | 预期 |
|------|------|------|
| D1-A1 | 完成一次压测后拉取 `/performance/tasks/{id}/results/` | 每条结果含 `p95`、`p99`、`max_response_time`、`error_classification` |
| D1-A2 | 拉取 `/performance/tasks/{id}/report/` | `report` 含 `avg_p95_ms`、`max_p99_ms`、`max_response_time_ms`、`error_classification` |
| D1-A3 | 旧任务迁移后仅历史数据 | 新字段为 0 或 `{}`，页面/API 不报错 |

## 业务断言（D2）

| 编号 | 场景 | 预期 |
|------|------|------|
| D2-A1 | 配置合法 `assertions`，接口返回 200 且 JSON 符合 | 失败率不含业务失败 |
| D2-A2 | 返回 200 但 JSON 不符合断言 | `assertion_failure` 增加，失败率上升 |
| D2-A3 | 非法 `extra_config` | 创建/更新任务接口返回 400 及明确错误信息 |

## 多阶段负载（D3）

| 编号 | 场景 | 预期 |
|------|------|------|
| D3-A1 | `stages` 各段时长之和 ≠ `run_time` | 保存任务失败 |
| D3-A2 | 合法多阶段 | Locust 按阶段改变并发，结果时序连续 |

## CSV 参数化（D4）

| 编号 | 场景 | 预期 |
|------|------|------|
| D4-A1 | 上传非 CSV 或超过 10MB | 校验失败 |
| D4-A2 | `per_iteration` | 多次请求按行轮询替换 `{{列名}}` |
| D4-A3 | `per_user` | 同一用户多次请求使用同一行数据 |

## 异常流程

- 空 CSV、非 UTF-8 无法解析：任务启动失败或读文件时报错信息可读。
- 仅 HTTP 错误：错误分类以 `http_status_error` 为主。
